Breaking: an injected `fetch` no longer turns off the missing-key check. A call routed to `etherscan-v2` with no key now throws `missing-api-key` before any request, whether `fetch` is set or not, and `dryRun()` returns `lookup: "skipped"` there instead of looking the contract up. A route whose `apiUrl` points at a proxy, with an injected `fetch` and no key, throws `missing-api-key` too. The new `handlerUrl` option says that your server handler adds the key: each Etherscan request goes to that URL with no key, other requests go to their explorer directly, and the routing table chooses as it does with an Etherscan key. Log lines, events, a dry run's `apiHost` and errors name the handler URL for those requests, so keep secrets out of it. A refusal of the handler names its code, such as `chain-not-allowed`; a 4xx refusal is not retryable and its hint points at the `createVerifyHandler` options. `ExplorerVerifyErrorOptions` gains `retryable`. A path such as `/api/verify` works in a browser page; elsewhere pass an absolute URL. The `handlerUrl` code loads on demand, so a bad value rejects the call when it starts, and a caller who never sets it does not download it. An Etherscan key next to `handlerUrl`, in `apiKeys` or as `route.apiKey` on Etherscan's API, throws `invalid-input` in every function. A result reached through the handler now carries the Etherscan page as `explorerUrl`. `apiKeys` now accepts only the backends that take a key there, `etherscan-v2`, `routescan` and `blockscout-hosted`, exported as the `ApiKeys` and `KeyedBackendName` types, so `apiKeys: { sourcify: "..." }` no longer compiles. Issue: https://github.com/aelmanaa/explorer-verify/issues/217

What should I do? In a browser, replace the URL-rewriting `fetch` and `route: { backend: "etherscan-v2" }` with `verify(input, { handlerUrl: "/api/verify" })`; keep `route.backend` if you want Etherscan on chains whose row lists Sourcify first. Keep `fetch` for logging, retries or tests; pass it next to `handlerUrl` if you need both. If you pointed `route.apiUrl` at your own proxy, use `handlerUrl` with Etherscan's default URL instead. Remove `sourcify`, `blockscout` and `etherscan-compatible` entries from `apiKeys`; a standalone explorer's key goes in `route.apiKey`.
