# 2026-11-12: The oldest Node 22 release the published packages run on

Audience: whoever changes `engines.node`, the CI test matrix or the build target. Assumes
[decision 0060](../decisions/0060-supported-node-versions-follow-lts.md).

This note gathers the facts behind [decision 0071](../decisions/0071-published-node-floor.md)
(issue [#393](https://github.com/aelmanaa/explorer-verify/issues/393)). Every package declared
`engines.node` `>=22.18.0`. That floor came from the repository's scripts and tests, which run
TypeScript natively, not from the published JavaScript.

## What the built code uses

The packages compile to ES2023 (`tsconfig.base.json`) and have no runtime dependencies. A search
of `dist/src` of the four packages, built from `main` at `6c61ec8` on 2026-11-12, finds these
version-sensitive features. The versions come from the Node.js API docs, read 2026-11-12.

| Feature                                                          | Where                                                  | First Node release                      |
| ---------------------------------------------------------------- | ------------------------------------------------------ | --------------------------------------- |
| Global `fetch`, `Request`, `Response`                            | every client, the server handler                       | 18.0.0 without a flag; stable in 21.0.0 |
| `AbortSignal.timeout`                                            | the flow and the HTTP layer                            | 17.3.0                                  |
| `globalThis.crypto.subtle`                                       | `internal/sha256.js`                                   | 19.0.0 without a flag                   |
| `Array.prototype.toSorted` (ES2023)                              | input building, the CLI, the build helpers             | runs on 22.0.0 (observed below)         |
| Import attributes, `import ... with { type: "json" }`            | `routing/table.js`, the CLI's `version.js`             | 18.20.0, 20.10.0, 21.0.0                |
| JSON modules without an `ExperimentalWarning`                    | the same two imports                                   | 22.12.0 (also 23.1.0, 20.18.3, 18.20.5) |
| Synchronous `import.meta.resolve` without a flag                 | the CLI's `version.js`                                 | 20.6.0                                  |
| `util.parseArgs` with `tokens`                                   | the CLI's `arguments.js`                               | runs on 22.0.0 (observed below)         |
| `fs/promises` `readdir` with `withFileTypes`, `realpath`, `stat` | `@explorer-verify/foundry`, `@explorer-verify/hardhat` | runs on 22.0.0 (observed below)         |

Everything but the JSON module warning is in Node 22.0.0. The Node.js ESM docs list "JSON modules
are no longer experimental" for v22.12.0, and the v22.12.0 release notes list "esm: mark import
attributes and JSON module as stable" (nodejs/node#55333). The same release turned on `require()` of
an ES module by default (nodejs/node#55085), still marked experimental: a CommonJS caller can load
the packages with `require()` from 22.12.0, with a warning.

## What the packages do on each release

Observed on 2026-11-12, macOS x64, with the official `node-v<version>-darwin-x64.tar.gz` binaries
from nodejs.org. The four packages were packed with `pnpm pack` (pnpm 12.16.1), installed with the
npm bundled with each Node into an empty folder, and run with
[`test/node-floor/smoke.mjs`](../../../test/node-floor/smoke.mjs): 17 checks that import every
entry, run `verify()`, `checkStatus()`, `explorer-verify/core`, the routing table, the server
handler, the Foundry and Hardhat helpers, and the `explorer-verify` bin, with no request leaving the
machine. The bin must write nothing on stderr.

| Node    | Result                                                                                                                                                                             |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 22.0.0  | The 13 library checks pass. The first bin check fails: the bin prints `ExperimentalWarning: Importing JSON modules is an experimental feature` on stderr, then the right envelope. |
| 22.11.0 | Same as 22.0.0.                                                                                                                                                                    |
| 22.12.0 | All 17 checks pass. Nothing on stderr.                                                                                                                                             |
| 22.18.0 | All 17 checks pass.                                                                                                                                                                |

On 22.0.0 and 22.11.0 the library works, but a call that loads the routing table prints the same
warning on the caller's stderr. With `--log-format json`, the CLI promises one JSON object per
stderr line, and the warning breaks that.

`require("explorer-verify")` from CommonJS throws `ERR_REQUIRE_ESM` on 22.0.0 and returns the
module on 22.12.0, with an `ExperimentalWarning` (observed the same day).

## Hardhat 3's own minimum

Hardhat's "Getting started" page lists "Node.js v22.13.0 or later" as a prerequisite of Hardhat 3
(read 2026-11-12). The `hardhat` 3.22.0 manifest declares no `engines` field (issue #393). A floor of
22.12.0 is below Hardhat 3's, so an adapter for Hardhat 3 meets explorer-verify's floor.
